# The typed IR

The first of the two representations of [002](002-architecture.md). It is a
tree, it is type-checked, and it still speaks Go: a range statement is a range
statement and a map index is a map index.

It exists for the passes that reason about the program as Go rather than as a
machine — inlining ([024](024-inlining-and-devirtualization.md)) and escape
analysis ([023](023-escape-analysis.md)) — and it is the last place where those
questions can be asked.

## Why not use the syntax tree

The syntax tree of [011](011-parser-and-ast.md) plus the type checker's result
maps is nearly this. Three differences make it not this:

1. **Implicit operations are explicit.** An assignment of a concrete value to an
   interface variable is a conversion node, not an assignment with unequal
   types. A method call on an addressable value that needs its address gets the
   address operation. Every implicit conversion the specification permits is a
   node.
2. **Names are resolved to objects.** An identifier is a pointer to the
   declaration, not a string to be looked up. Shadowing is gone.
3. **The tree is mutated.** Inlining rewrites it in place. The syntax tree is an
   input and is not owned.

The conversion is one walk over the checked tree, producing IR and consulting the
checker's recorded types and definitions.

## The type boundary

[002](002-architecture.md) forbids anything below `ssa` from importing `types2`.
The IR is where that boundary is drawn, and it is drawn by one type:

```go
type Type struct {
    Kind    Kind      // the machine-relevant classification
    Size    int64     // bytes
    Align   int64     // bytes
    PtrBits []byte    // one bit per pointer-sized word: 1 if it holds a pointer
    Elem    *Type     // pointer, slice, array, chan, map value
    Key     *Type     // map key
    Fields  []Field   // struct and tuple
    Len     int64     // array length
    Name    string    // diagnostics only; nothing below the IR may branch on it
}
```

One field on that struct is not a layout fact and is there anyway:
`EmptyIface`, for `Kind == Interface`. Both kinds of interface are two pointer
words, so size, alignment and pointer map are identical and none of them tells
the two apart. What differs is **the meaning of the first word**: an empty
interface holds a `*_type` and a non-empty one holds an `*itab`. Equality calls
`runtime.efaceeq` for one and `runtime.ifaceeq` for the other, and calling the
wrong one makes the runtime read a function pointer at the wrong offset and
jump through it.

So it passes the boundary's own test. It is not a name and not a method set; it
is which of two layouts a word has, which is as machine-relevant as the pointer
map. It was added when the SSA builder reached for the distinction, found
nothing, and stopped rather than guessing, which is the behaviour the rule
against workarounds is meant to produce.

`PtrBits` is the field the backend actually needs and the one most easily got
wrong. It is computed once, by the layout pass in this package, from
[030](030-abi.md)'s rules. Nothing recomputes it. An earlier version of this
spec attributed the computation to [012](012-type-checking.md), which is where
the *conversion* from a checker type happens, not the layout.

There is one kind that is not a Go type. **`Tuple`** is the type of a
multi-value expression: a call with several results, a two-value map read, type
assertion or channel receive. No variable has one. It exists because such an
expression still needs a type here, and the alternative is a nil type that every
consumer special-cases. Its layout is a struct's and is deliberately **not**
[030](030-abi.md)'s result layout: results are assigned to registers and the
stack by the calling convention, so reading a tuple's field offsets as an ABI
answer would be wrong.

The rule this enforces is worth stating as a rule: **below the IR, a type is a
size, an alignment, and a pointer map.** Not a name, not a method set, not an
underlying type.

## Node set

Nodes are structs with a `Pos` and a `*Type`. The set is smaller than the syntax
tree's, because the syntax distinctions that carry no semantics are gone:

| Group | Nodes |
| --- | --- |
| Values | constant, local, global, field, index, deref, address-of |
| Operations | unary, binary, compare, convert, call, assign |
| Control | if, for, switch, case, select, block, goto, label, return, break, continue |
| Go-specific | range, type assertion, type switch, closure, defer, go, send, receive, make, append, copy, delete, panic, recover, composite literal, slice expression, close, print, println |

Eight of those were added after the first two consumers were written, and the
way they were found is worth recording. Without `assign`, `case` and a `for`
post statement, the SSA builder encoded an assignment as a binary operation with
no operator and a clause as a block. Without `composite literal`, `slice
expression`, `close`, `print` and `println`, the IR builder encoded a literal as
`new`, a slice expression as an index with extra operands, and the three
builtins as calls to function objects it invented.

Every one of those is a workaround, and a workaround in the IR is a lie that
each later pass has to be told about separately. They are nodes now.

The **Go-specific** row is the important one, because it is the list that must be
empty by the end of SSA construction.

## The lowering obligation

[002](002-architecture.md) states that no Go construct survives into SSA. That
claim is only meaningful if the list is exhaustive, so here it is, with where
each one goes. This table is the contract between this spec,
[021](021-ssa-construction.md), and [031](031-runtime-lowering.md).

| Construct | Becomes |
| --- | --- |
| `range` over slice, array, pointer-to-array | an index loop with the bound hoisted |
| `range` over string | a loop with an inlined UTF-8 decode |
| `range` over map | `runtime.mapiterinit` / `mapiternext` and a loop |
| `range` over channel | a receive loop that exits on a closed channel |
| `range` over integer | a counted loop |
| `range` over function | a call taking the body as a closure |
| map read, write, delete | `runtime.mapaccess1`, `mapaccess2`, `mapassign`, `mapdelete` |
| channel send, receive | `runtime.chansend1`, `chanrecv1`, `chanrecv2` |
| `select` | `runtime.selectgo` plus a jump table on its result |
| type assertion | a type descriptor comparison, or `runtime.assertE2I` / `assertI2I` |
| type switch | a hash lookup or a chain of descriptor comparisons |
| interface conversion | an itab reference plus a two-word construction, or `runtime.convT*` |
| method value | a closure holding the receiver |
| method expression | a reference to the method's function symbol |
| closure | a heap or stack closure object, per [023](023-escape-analysis.md) |
| `defer` | open-coded where possible, otherwise `runtime.deferproc`; see [033](033-closures-defer-panic.md) |
| `go` | `runtime.newproc` with an argument frame |
| `panic`, `recover` | `runtime.gopanic`, `runtime.gorecover` |
| `append` | an inlined fast path plus `runtime.growslice` |
| `copy` | `runtime.memmove`, or an inlined move for small constant sizes |
| `make` | `runtime.makeslice`, `makemap`, `makechan` |
| `new`, escaping composite literals | `runtime.newobject` |
| string concatenation | `runtime.concatstring{2,3,4,5}` |
| string comparison | `runtime.memequal` plus a length check |
| `string` ↔ `[]byte`, `[]rune` | `runtime.stringtoslicebyte` and the rest of that family |
| struct and array comparison | field-wise comparison, or a generated equality function |
| slice expression, including 3-index | bounds checks plus pointer arithmetic |
| complex arithmetic | real and imaginary component operations |
| multi-value assignment | temporaries in the order the specification requires |
| package initialisation | one `init` function, ordered by [012](012-type-checking.md) |
| composite literal | a frame or heap allocation plus element stores, per [023](023-escape-analysis.md) |
| slice expression, including 3-index | bounds checks plus pointer arithmetic |
| `close` | `runtime.closechan` |
| `print`, `println` | `runtime.print*` per argument type, bracketed by `printlock` and `printunlock` |
| variadic call | the variadic arguments packed into a slice at the call site |
| `unsafe.Add` | pointer arithmetic |
| `unsafe.Slice`, `unsafe.String` | a slice or string header built from a pointer and a length, with the length checked |
| `unsafe.SliceData`, `unsafe.StringData` | the data pointer read out of a header |

The `unsafe` rows are operations and not calls, and the distinction is the
point: none of them reaches the runtime. Building them as a call to a global
named `unsafe.Add` makes every later pass recognise an intrinsic by matching a
string, and a pass that forgets to match it emits a call to a function that does
not exist.

The variadic row is one the spec did not have, and it has to be here rather
than later: the element type of the packed slice is a fact only the type
checker knows, so no pass below the IR can recover it.

A construct that is not in this table and not in the IR node set does not exist.
Adding one to the IR without adding a row is the bug this table is here to make
visible.

That claim was false when it was first written. `close`, `print`, `println`,
composite literals, slice expressions and variadic packing were all absent from
both the table and the node set, and the builder had to invent an encoding for
each. The claim is a good rule and it only means something if the table is kept
complete, which is why every gap found since is listed above rather than
patched around.

## Order of evaluation

The specification pins the order of evaluation of function calls, method values,
communication operations, and index expressions within a statement. The IR is
where that order becomes explicit, by introducing temporaries, and it is the last
place it can be, because SSA construction is free to reorder anything the data
dependencies allow.

Getting this wrong produces programs that work until they are optimised. The
corpus in [004](004-conformance.md) L2 has a directory of exactly these cases.

## Testing

- The lowering table above as a checklist: for each row, a program using the
  construct, compiled, run, and compared against `gc` under
  [004](004-conformance.md) L3.
- An assertion, run after SSA construction, that no Go-specific node reached it.
  This is a compiler-internal invariant check and it is enabled in tests always.
- Evaluation order tests from Go's `test/` corpus.
