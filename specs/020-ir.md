# The typed IR

The first of the two representations of [002](002-architecture.md). It is a
tree, it is type-checked, and it still speaks Go: a range statement is a range
statement and a map index is a map index.

It exists for the passes that reason about the program as Go rather than as a
machine, inlining ([024](024-inlining-and-devirtualization.md)) and escape
analysis ([023](023-escape-analysis.md)), and it is the last place where those
questions can be asked.

## Why not use the syntax tree

The syntax tree of [011](011-parser-and-ast.md) plus the type checker's result
maps is nearly this. Three differences make it not this:

1. **Implicit operations are explicit.** An assignment of a concrete value to an
   interface variable is a conversion node, not an assignment with unequal
   types. A method call on an addressable value that needs its address gets the
   address operation. Every implicit conversion the specification permits is a
   node.
2. **Names are resolved to objects.** An identifier is a pointer to the
   declaration, not a string to be looked up. Shadowing is gone.
3. **The tree is mutated.** Inlining rewrites it in place. The syntax tree is an
   input and is not owned.

The conversion is one walk over the checked tree, producing IR and consulting the
checker's recorded types and definitions.

## The type boundary

[002](002-architecture.md) forbids anything below `ssa` from importing `types2`.
The IR is where that boundary is drawn, and it is drawn by one type:

```go
type Type struct {
    Kind    Kind      // the machine-relevant classification
    Size    int64     // bytes
    Align   int64     // bytes
    PtrBits []byte    // one bit per pointer-sized word: 1 if it holds a pointer
    Elem    *Type     // pointer, slice, array, chan, map value
    Key     *Type     // map key
    Fields  []Field   // struct
    Len     int64     // array length

    EmptyIface bool   // Kind == Interface: no methods, so the first word is a *_type

    // The descriptor group. Read by the descriptor writer of
    // 032-type-descriptors-and-itabs.md and by diagnostics, and by nothing
    // that generates an instruction.
    Name         string   // "internal/goarch.ArchFamilyType", "int"; empty for a type literal
    PkgPath      string   // the import path of the declaring package
    Basic        string   // the predeclared underlying type: "int" for type T int
    Instantiated bool     // an instantiation of a generic type
    Methods      []Method // the method set of the *pointer* to this type, sorted by name
}
```

`Field` carries the same split. `Name`, `Type` and `Offset` are layout, and
`Tag`, `Embedded` and `Pkg` are descriptor facts: two struct types that differ
only in a tag are different types, and a struct descriptor points at the import
path of its first unexported field.

`Method` is `Name`, `Pkg` and `PtrOnly`, and **the signature is absent**. That
is the one hole the boundary still has, and the blocked-row table below is
where it is paid for. The set is the *pointer*'s, because it is the larger of
the two, and `PtrOnly` says which entries the value type's set drops. A nil
slice on a defined type is not "no methods": the converter sets the field for
every defined type, empty set included, so that an empty method set is knowable
rather than merely unrecorded.

`EmptyIface` is neither a layout fact nor a descriptor fact, and code that
generates instructions branches on it anyway. Both kinds of interface are two
pointer words, so size, alignment and pointer map are identical and none of
them tells the two apart. What differs is **the meaning of the first word**: an empty
interface holds a `*_type` and a non-empty one holds an `*itab`. Equality calls
`runtime.efaceeq` for one and `runtime.ifaceeq` for the other, and calling the
wrong one makes the runtime read a function pointer at the wrong offset and
jump through it.

So it passes the boundary's own test. It is not one of the descriptor facts
restated; it is which of two layouts a word has, which is as machine-relevant
as the pointer map. It was added when the SSA builder reached for the
distinction, found nothing, and stopped rather than guessing, which is the
behaviour the rule against workarounds is meant to produce.

`PtrBits` is the field the backend actually needs and the one most easily got
wrong. It is computed once, by the layout pass in this package, from
[030](030-abi.md)'s rules. Nothing recomputes it. An earlier version of this
spec attributed the computation to [012](012-type-checking.md), which is where
the *conversion* from a checker type happens, not the layout.

Two kinds are not Go types. **`Void`** is the type of an expression with no
value, and of a function with no results; it has size zero and no pointers.
**`Tuple`** is the type of a multi-value expression: a call with several
results, a two-value map read, type assertion or channel receive. No variable
has one. It exists because such an
expression still needs a type here, and the alternative is a nil type that every
consumer special-cases. Its layout is a struct's and is deliberately **not**
[030](030-abi.md)'s result layout: results are assigned to registers and the
stack by the calling convention, so reading a tuple's field offsets as an ABI
answer would be wrong.

The rule this enforces used to be one rule and is now two. `ir/type.go`'s
header states both:

- **Nothing that generates code may branch on a descriptor field.** Two types
  with the same kind, size and pointer map compile to the same instructions
  however their names or method sets differ.
- **Nothing that writes a descriptor may guess a descriptor field.** A field
  the checker did not supply is refused by name, never filled in.

The first is the old rule narrowed to its subject: below the IR, a type *that
generates code* is a size, an alignment and a pointer map, not a name, not a
method set, not an underlying type. The second is what
[032](032-type-descriptors-and-itabs.md) found when every defined type in the
standard library was refused. A descriptor is data the runtime and `reflect`
read, and it carries facts no instruction depends on, so those facts have to
cross the boundary or nobody below it can write one. They cross in one marked
group, and a gap in that group is a refusal by name rather than a zero that
reads as a fact.

## Node set

Nodes are structs with a `Pos` and a `*Type`. The set is smaller than the syntax
tree's, because the syntax distinctions that carry no semantics are gone. The
table below is the whole set, read off the `Op` constants of `ir/node.go`. A
node in one and not the other is a bug in whichever was edited last.

| Group | Nodes |
| --- | --- |
| Values | constant, local, global, field, index, deref, address-of |
| Operations | unary, binary, compare, convert, call, assign |
| Control | if, for, switch, case, block, goto, label, return, break, continue |
| Go-specific | range, type assertion, type switch, closure, defer, go, send, receive, select, make, append, copy, delete, panic, recover, len, cap, new, complex, real, imag, clear, min, max, composite literal, slice expression, close, print, println |
| Go-specific, `unsafe` | `unsafe.Add`, `unsafe.Slice`, `unsafe.SliceData`, `unsafe.String`, `unsafe.StringData` |

The **Go-specific** rows are the important ones, because they are the list that
must be empty by the end of SSA construction. `ir.IsGoSpecific` is that list in
code, and `select` belongs to it: a `select` is a `runtime.selectgo` call and a
jump table, not a control form the SSA builder can build.

Twelve of those nodes were added after the first two consumers were written, and
the way they were found is worth recording. Without `assign` and `case`, the SSA
builder encoded an assignment as a binary operation with no operator and a
clause as a block. Without `composite literal`, `slice expression`, `close`,
`print` and `println`, the IR builder encoded a literal as `new`, a slice
expression as an index with extra operands, and the three builtins as calls to
function objects it invented. Without the five `unsafe` nodes it built a call to
a global named `unsafe.Add`, which makes every later pass recognise an intrinsic
by matching a string.

A thirteenth gap was a field rather than a node. `Node` had no post statement
for a `for`, and the first consumer put it in `Else`, which an `if` uses for
something else entirely. `Node.Post` exists now.

Every one of those is a workaround, and a workaround in the IR is a lie that
each later pass has to be told about separately. They are nodes now.

## The lowering obligation

[002](002-architecture.md) states that no Go construct survives into SSA. That
claim is only meaningful if the list is exhaustive, so here it is, with where
each one goes. This table is the contract between this spec,
[021](021-ssa-construction.md), and [031](031-runtime-lowering.md).

`ir/lower.go` performs the table. It runs first in the driver's pass list, and
[021](021-ssa-construction.md)'s guard is unchanged behind it: `ssa.Build` still
refuses every Go-specific node, so a row that is not built here is refused
there rather than handled in two places. Lowering does not stop at the first
row it cannot perform, because the count of causes is what says which row to
build next.

Most of the table is built. `ir/lower_corpus_test.go` measures the reach with
the pass and without it over one run of one package list, because the two
corpus walks of this deck sample differently and a number from one is not
comparable with a number from the other. [003](003-sequencing.md) carries the
counts, and they are not repeated here: a count copied into prose is the drift
`internal/hygiene` exists to catch.

The **State** column is the contract's ledger. `not built` means the node
survives the pass and construction refuses the function.

| Construct | Becomes | State |
| --- | --- | --- |
| `range` over slice, array, pointer-to-array | an index loop with the bound hoisted | built |
| `range` over integer | a counted loop | built, one variable only |
| `range` over string | a loop with an inlined UTF-8 decode | not built |
| `range` over map | `runtime.mapIterStart` / `mapIterNext` and a loop | built. No condition of its own: the loop ends when the iteration sets the `maps.Iter`'s first word to nil. The two names are the compiler's entry points and `mapiterinit` / `mapiternext` are not: those still exist, in `runtime/linkname_shim.go`, taking a `*runtime.linknameIter` rather than a `*maps.Iter`, and calling one with a `maps.Iter` frame slot writes past the end of it |
| `range` over channel | a receive loop that exits on a closed channel | built. No condition and no index: the loop leaves through `runtime.chanrecv2` saying the channel is closed and drained |
| `range` over function | a call taking the body as a closure | not built |
| map read, write, delete | `runtime.mapaccess1`, `mapaccess2`, `mapassign`, `mapdelete` | built, in both the one-value and the two-value read. The key crosses each call as the address of a frame slot and the element never crosses: each of the first three returns a pointer into the table and the value is read or written through it. A destination is `mapassign` and a value is `mapaccess1`, and one router in `ir/lower.go` decides which, because lowering a destination as a value stores into the runtime's zero value and drops the write |
| channel send, receive | `runtime.chansend1`, `chanrecv1`, `chanrecv2` | built, in both the one-value and the two-value form. The element crosses each call as the address of a frame slot, and a send copies into a slot of its own rather than passing the address of the program's variable |
| `select` | `runtime.selectgo` plus a jump table on its result | built. `select {}` is refused: it parks the goroutine for good, which is `runtime.block`, and `rtsym` does not carry it |
| type assertion | a comparison of the interface's first word against the target's descriptor, or `runtime.typeAssert` where the target is an interface | built for a concrete target, in both the one-value and the two-value form. The one-value form calls `runtime.panicdottypeE` in the failing arm and falls through in the other, which needs no join because the symbol does not return. An interface target is refused: its answer is an itab, which [032](032-type-descriptors-and-itabs.md) does not write. `runtime.assertE2I` and `assertI2I` are not what `gc` emits for this row and `assertI2I` is not in `go1.27` at all |
| type switch | an `OSwitch` on the interface's first word, or `runtime.interfaceSwitch` where a case names an interface | built for concrete cases, `case nil` and `default` included. The clause variable takes the clause's own type where the clause names exactly one and the guard's type everywhere else, which is the type the checker gave the clause's object. A case that names an interface is refused, for the reason the row above gives |
| interface conversion | an itab reference plus a two-word construction, or `runtime.convT*` | not built |
| method value | a closure holding the receiver | not built |
| method expression | a reference to the method's function symbol | not built |
| closure | a heap or stack closure object, per [023](023-escape-analysis.md) | built, always on the heap; every capture is by reference and moves the variable into a heap cell of its own ([033](033-closures-defer-panic.md)) |
| `defer` | open-coded where possible, otherwise `runtime.deferproc`; see [033](033-closures-defer-panic.md) | `runtime.deferproc` built, arguments included: the builder puts the call in a literal that captures the operands. A deferred builtin such as `close`, `copy` or `delete` has no function value to give the runtime and is refused, and so is a method of an interface |
| `go` | `runtime.newproc` with an argument frame | built, on the same terms as `defer` |
| `panic` | `runtime.gopanic` | built, and the operand is the limit: a `panic` of a concrete value needs the interface conversion row above and is refused, and a `panic` of an interface value that fires dies in the runtime with `name offset out of range` ([033](033-closures-defer-panic.md)) |
| `recover` | `runtime.gorecover` | built in both positions. The call is the deferred function's own in each: `runtime.gorecover` counts the frames between itself and `runtime.gopanic` and recovers only where there is exactly one, so a pass that moved the call into a helper would build a recover that never recovers |
| `append` | an inlined fast path plus `runtime.growslice` | built, in both the element form and the `...` form. The capacity test is unsigned, `runtime.growslice` takes the *element* descriptor and returns a header whose length is already the new one, and every operand is evaluated into a temporary before the branch, which is the order `walkAppend` requires: a panic an argument raises has to happen before the slice is modified in a way the program can see. The `...` operand may be a string where the element is a byte. The copy is `runtime.memmove`, under a test that the operand holds something, because the address the move starts at is one past the end of the allocation when it does not |
| `copy` | `runtime.memmove`, or an inlined move for small constant sizes | built |
| `make` | `runtime.makeslice`, `makemap`, `makechan` | all three built; a `make` whose type needs a descriptor the boundary cannot name is refused. `makemap` takes three parameters and the third is last, a `*maps.Map` the runtime uses instead of allocating, and this compiler passes nil for the reason [023](023-escape-analysis.md) gives |
| `new`, escaping composite literals | `runtime.newobject` | built, except where the allocated type needs a descriptor the boundary cannot name: a function's signature, or a generic instantiation's type arguments |
| string concatenation | `runtime.concatstring{2,3,4,5}` | built, in `ssa/build.go`; a chain of more than five operands nests, because the flattening is bounded by what `rtsym` carries |
| string equality | `runtime.memequal` plus a length check | built, in `ssa/decompose.go`, which is where the two headers are parts |
| string ordering, `<` `<=` `>` `>=` | `runtime.cmpstring`, then an integer comparison of its result against zero | built, in `ssa/decompose.go` |
| `string` to `[]byte` or `[]rune`, and back | `runtime.stringtoslicebyte` and the rest of that family | built, all five: `stringtoslicebyte`, `stringtoslicerune`, `slicebytetostring`, `slicerunetostring` and `intstring` for `string(r)`. Every one of them allocates, which is the row and not a detail: a `[]byte(s)` that shared the string's bytes would let a write through the slice change a string. Each takes a buffer and this pass passes nil, so the runtime allocates, for the reason the `make` row gives. `slicebytetostring` is the one whose operand is decomposed: its parameters are the data pointer and the length rather than the header |
| struct and array comparison | field-wise comparison, or a generated equality function | not built |
| slice expression, including 3-index | bounds checks plus pointer arithmetic | built, except a three-index slice of a string |
| complex arithmetic | real and imaginary component operations | not built |
| multi-value assignment | temporaries in the order the specification requires | not built |
| package initialisation | one `init` function, ordered by [012](012-type-checking.md) | not built |
| composite literal | a frame or heap allocation plus element stores, per [023](023-escape-analysis.md) | struct, array, slice and map built; a literal whose type needs a descriptor the boundary cannot name is refused. A map literal is a `makemap` sized to the number of elements and one insert per element, in source order |
| `len`, `cap` of a slice or string | the length or capacity word read out of the header | built |
| `len` of an array or pointer-to-array | a constant, with the operand still evaluated for its effects | built |
| `len` of a map | the count field read out of the map header, behind a nil check | built, and it is the one layout of the runtime's that this pass reads. No symbol returns a map's length, `gc` reads the word inline in `ssagen.referenceTypeBuiltin`, and `internal/runtime/maps` writes "Must be first (known by the compiler, for len() builtin)" above the field |
| `len`, `cap` of a channel | `runtime.chanlen`, `runtime.chancap` | built. A call and not a load: a nil channel has length and capacity zero and no `hchan` to read them from, and `gc` stops itself with "cannot inline len(chan)" for the same reason |
| `clear` of a slice | a zeroing of the elements, `runtime.memclr*` for a large one | built |
| `clear` of a map | `runtime.mapclear` | built |
| `min`, `max` | a compare and a select per operand, left to right | built for integers; a float's NaN is refused |
| `real`, `imag` | the component read out of the pair | not built |
| `close` | `runtime.closechan` | built |
| `print`, `println` | `runtime.print*` per argument type, bracketed by `printlock` and `printunlock` | built, except an operand whose symbol `gc` instantiates per type: an interface, a slice, a complex |
| variadic call | the variadic arguments packed into a slice at the call site | built, by `ir.Build`, and the literal it makes is lowered here |
| `unsafe.Add` | pointer arithmetic | built |
| `unsafe.SliceData`, `unsafe.StringData` | the data pointer read out of a header | built |
| `unsafe.Slice`, `unsafe.String` | a slice or string header built from a pointer and a length, with the length checked | not built |

The rows that are not built are not a flat list. Each large one is blocked on
something else this deck owes:

| Blocked row | Waiting on |
| --- | --- |
| an assertion or a type switch case naming an interface, and a conversion to an interface with methods | the itab of the (interface, concrete type) pair, which [032](032-type-descriptors-and-itabs.md) does not write. An itab holds each method's ABI wrapper, so the row also waits on the method **signature** the type boundary drops and on the two wrappers `gc` generates beside every method. The method set itself crosses the boundary now, in `Type.Methods` |
| a method value, and a named result a closure captures | the first binds the receiver by value rather than through a heap cell, and the second shares its storage with the single exit of a function that defers ([033](033-closures-defer-panic.md)) |
| an allocation or a literal whose type needs a descriptor | a generic instantiation's type arguments, which the boundary does not carry; [032](032-type-descriptors-and-itabs.md) refuses them by name rather than filling them in |

`ir/lower_corpus_test.go` prints the count per cause, largest first, and that
output is the order to work in. It is not repeated here, because a per-row
count that is copied into prose is the drift `internal/hygiene` exists to
catch and this table is not one of the places it reads.

The `unsafe` rows are operations and not calls, and the distinction is the
point: none of them reaches the runtime. Building them as a call to a global
named `unsafe.Add` makes every later pass recognise an intrinsic by matching a
string, and a pass that forgets to match it emits a call to a function that does
not exist.

The variadic row has to be in the IR rather than later: the element type of the
packed slice is a fact only the type checker knows, so no pass below the IR can
recover it.

A construct that is not in this table and not in the IR node set does not exist.
Adding one to the IR without adding a row is the bug this table is here to make
visible.

## Order of evaluation

The specification pins the order of evaluation of function calls, method values,
communication operations, and index expressions within a statement. The IR is
where that order becomes explicit, by introducing temporaries, and it is the last
place it can be, because SSA construction is free to reorder anything the data
dependencies allow.

Getting this wrong produces programs that work until they are optimised. The
corpus in [004](004-conformance.md) L2 has a directory of exactly these cases.

## Testing

- The lowering table above as a checklist, in `ir/lower_test.go`: for each row
  that is built, a program using the construct, lowered and checked. The
  stronger form, compiled and run and compared against `gc` under
  [004](004-conformance.md) L3, is `internal/e2e`'s, and it reaches the rows a
  variadic call and an allocation use.
- An assertion that no Go-specific node reaches SSA. `ir.HasGoSpecific` is that
  assertion and `ir/node_test.go` exercises it, but nothing in the pipeline
  calls it. What enforces the invariant today is `ssa.Build`, which refuses a
  Go-specific node as it reaches the statement or expression switch.
- Evaluation order tests from Go's `test/` corpus. Not written. `ir/build.go`
  does introduce the temporaries, in `ordered`, `stable` and `temp`.

Two corpora are gated. `ir/build_test.go` builds 536 packages of the Go
distribution into 39,947 functions and 4,188,075 nodes.
`ir/lower_corpus_test.go` runs the pass over the same tree and counts every row
it refuses, by cause, which is where the ledger's numbers come from. `ir` is
above the 90% coverage gate.

## What was wrong

The spec said the node set is smaller than the syntax tree's and complete. The
code has fourteen ops the table never listed: `len`, `cap`, `new`, `complex`,
`real`, `imag`, `clear`, `min`, `max`, and the five `unsafe` intrinsics. The
table also filed `select` under Control, where the code files it under the set
that must be lowered away. This was found by reading the `Op` constants of
`ir/node.go` against the table, one by one; the table above is now that list.

The node-set gap and the lowering-table gap were one gap. Seven of those
fourteen ops, `len`, `cap`, `clear`, `min`, `max`, `real` and `imag`, had no row
in the lowering table either. Fixing the node set alone would have left this
spec's own rule unenforced: a construct in the IR with no row saying what it
becomes is exactly what the rule exists to make visible. Both are fixed above.

The spec said eight nodes were added after the first consumers. Twelve were,
plus one field. The count came from the two "added after the fact" blocks of
`ir/node.go`, which hold `OAssign`, `OCase`, `OCompositeLit`, `OSlice`,
`OClose`, `OPrint`, `OPrintln` and the five `OUnsafe*` ops, and from
`Node.Post`, whose own comment records that the first consumer put a `for` post
statement in `Else`.

The spec said one kind is not a Go type. Two are: `Void` and `Tuple`, both in
`ir/type.go`.

The spec presented the lowering table as a contract between three specs and
said nothing about who performs it. For a time nobody did. This was found by
listing `ir/`: four files, none of them a pass, so the contract had no
performer and every row of it was an SSA construction refusal.
`ir/lower.go` is the performer now, and the **State** column exists so that the
same question has an answer per row rather than per spec.

The type boundary section listed nine fields of `Type` and the code has
fifteen. `PkgPath`, `Basic`, `Instantiated` and `Methods` were all missing, and
`Name` was annotated "diagnostics only", which stopped being true when
[032](032-type-descriptors-and-itabs.md)'s descriptor writer began reading it.
`Field` was not shown at all and carries `Tag`, `Embedded` and `Pkg` beside its
three layout fields, and `Method` is a type this spec never mentioned. The
listing above is `ir/type.go`'s.

The one rule the boundary enforced is two rules. The spec stated only the
first, that a type below the IR is a size, an alignment and a pointer map, and
`ir/type.go`'s header records why that was not enough: a descriptor carries
facts no instruction depends on, and a boundary that dropped them left every
defined type in the standard library refused. The second rule is that nothing
writing a descriptor may guess one of those facts. Both are stated above, in
the header's own words.

The blocked-row table said interface conversion waits on the method set. It
waits on each method's **signature**. `Type.Methods` crosses the boundary now,
and `ir.Method`'s own comment says what is still absent: a descriptor's
`Mtyp` offset needs the method's type with the receiver removed, and zero is a
legal `Mtyp` meaning "unexported, and `reflect` may not call it", so a zero
there would be read as a fact rather than as a gap. `make` of a slice of a
type with methods is refused for exactly that reason, and the probe corpus
records it.

**Three string rows were wrong, and one was missing.** Concatenation is built,
in `ssa/build.go`'s `concat`, which flattens a chain up to the five operands
`rtsym` has a symbol for and nests beyond that. Equality is built, in
`ssa/decompose.go`, which is where the two headers exist as parts for
`runtime.memequal` to take. Ordering had no row at all, and
`ssa/decompose.go`'s `expandStringOrder` says so in the code: the runtime
compares two strings with `cmpstring` and the comparison against zero is then
an ordinary integer one. All three are rows above now. The probe `string-ops`
concatenates, indexes, takes a length and orders in one program, and it agrees
with `gc`.

Four **State** cells claimed more than the pass performs, and the corpus names
each cause. A `panic` is built and its operand is not: a `panic` of a concrete
value needs the interface conversion row, and a `panic` of an interface value
that does fire dies in the runtime, which
[033](033-closures-defer-panic.md) records. `print` and `println` refuse an
operand whose runtime symbol `gc` instantiates per type, which is an interface,
a slice or a complex. `new`, `make` and a composite literal refuse a type whose
descriptor the boundary cannot name, which is a function's signature or a
generic instantiation's type arguments. A deferred builtin has no function
value to give `runtime.deferproc` and is refused.

The claim that a construct absent from the table does not exist was false when
it was first written. `close`, `print`, `println`, composite literals, slice
expressions and variadic packing were all absent from both the table and the
node set, and the builder had to invent an encoding for each. The claim is a
good rule and it only means something if the table is kept complete, which is
why every gap found since is listed here rather than patched around.
