# Packages that are reported but not gated.
#
# An entry here is a debt with a name on it. It says that a package ships below
# the coverage gate and that somebody decided this on purpose, so the reason is
# mandatory and covercheck rejects an entry without one. "hard to test" is not
# a reason; "the darwin/arm64 encoder path needs a device, and the table it
# drives is checked by golden files instead" is.
#
# Format, one package per line:
#
#	golang.design/x/nanogo/internal/thing  # why the gate is off, and what replaces it
#
# The number is still printed for an excluded package on every run. An
# exclusion removes the gate, never the measurement.
#
golang.design/x/nanogo/cmd/nanogo  # one statement, the process boundary: it hands os.Args and the standard streams to driver.Run and exits with its result. Coverage cannot see it because the only test that runs it, driver's end-to-end toolexec test, runs it as a separate process. The gate that replaces it is that test: it builds this binary and drives a real `go build -toolexec` with it, so a broken main fails the build rather than the coverage number. Delete this entry if main ever grows a second statement.
golang.design/x/nanogo/types2  # a fork, not written code. specs/012 takes cmd/compile/internal/types2 and re-points it at nanogo's syntax tree, and the gate that replaces this one is upstream's own test suite, ported with the sources: 613 subtests and a 375-package errorcheck corpus, all passing, plus TestChecksOwnSource type-checking nanogo's own source and TestAgreesWithGoTypesOnStdlib agreeing with go/types on 14 standard library packages. The uncovered tenth is upstream code its own suite does not reach; writing nanogo tests for it would test upstream, not the port. Delete this entry if nanogo ever starts writing checker logic of its own rather than porting it.
golang.design/x/nanogo/types2/errors  # 13 statements of vendored error codes, carried verbatim beside the checker because it is internal to the Go repository. The uncovered ones are String cases for codes the corpus does not yet provoke. There is nothing here to test that is not upstream's.
golang.design/x/nanogo/types2/gen  # the rewrite generator of specs/012. Its gate is not statement coverage but three tests that check the thing that can actually go wrong: TestGenerate fails when the tree drifts from what the table produces, TestIdempotent fails when a second run differs, and TestEveryUpstreamTestIsAccountedFor fails when an upstream test file is neither ported nor listed as skipped with a reason. The uncovered statements are error paths for a malformed table, which cannot occur without a broken commit that those three tests already reject.
